01

The "Drive-Centric" Architecture

Why Microservices?

IntervYouAI handles two very different workloads. First, it manages TPO (Training and Placement Officer) data, student profiles, and JWT authentication. Second, it runs heavy LLM processing, vector searches (FAISS), and speech-to-text for AI interviews.

Instead of a massive Monolith, we split it:

  • Java (Spring Boot) handles the "Institutional ERP" (Management, Auth, Drives) because Java is strictly typed, robust, and industry-standard for business logic.
  • Python (FastAPI) handles the "AI Execution" because Python has the best ecosystem for ML, PyTorch, and LangChain.
💡
The "Why" for your Interview

If an interviewer asks "Why didn't you just write the whole thing in Python?", tell them: Separation of Concerns and Ecosystem matching. Java handles transactional business rules perfectly with Hibernate, while Python is optimized for the AI inference. We scale the Python containers independently when AI load is high.

Crucial Decision: Asynchronous Communication via Kafka

When an interview finishes, the AI Engine takes time to generate feedback, scores, and transcripts. If the Java backend used a normal HTTP call and waited for this, the user's browser would freeze, and the connection might time out.

Python: "I just finished analyzing a 30-minute interview. Generating feedback..."
MESSAGE BROKER: { topic: 'interview-feedback', id: '123' }
Java: "I'm listening to the Kafka topic. I got the feedback, updating PostgreSQL now!"
@KafkaListener(
    topics = "${spring.kafka.topics.feedback}", 
    groupId = "backend-core-group"
)
@Transactional
public void consumeFeedback(InterviewFeedbackEvent event) {
    UUID sessionUuid = UUID.fromString(event.getSessionId());
    InterviewSession session = sessionRepository
        .findById(sessionUuid)
        .orElseThrow();

    session.setOverallScore(event.getOverallScore());
    sessionRepository.save(session);
}

We tell Spring to constantly listen to the Kafka Topic.

If an error happens while saving (like the DB goes down), @Transactional rolls back the database change, ensuring we don't save half the data.

02

The Edge: API Gateway & Security

The Bouncer at the Door

Instead of the React frontend trying to memorize port 8081 for Java and port 8000 for Python, we put an API Gateway (Port 8080) in front. It acts as a Reverse Proxy.

spring:
  cloud:
    gateway:
      mvc:
        routes:
          - id: ai_engine
            uri: http://localhost:8000
            predicates:
              - Path=/api/engine/**
          - id: backend_core
            uri: http://localhost:8081
            predicates:
              - Path=/api/core/**

If the URL starts with /api/engine, send it to Python silently.

If it starts with /api/core, send it to Java.

The frontend only ever talks to port 8080. It doesn't know microservices exist!

JWT Authentication Filter

In the Java backend, security is handled by a Filter. It checks every request for a JSON Web Token (JWT).

protected void doFilterInternal(
    HttpServletRequest request, 
    HttpServletResponse response, 
    FilterChain filterChain) {
    
    String jwt = parseJwt(request);
    if (jwt != null && jwtUtils.validateJwtToken(jwt)) {
        String email = jwtUtils.getEmailFromJwtToken(jwt);
        UserDetails userDetails = userDetailsService
            .loadUserByUsername(email);
            
        SecurityContextHolder.getContext()
            .setAuthentication(authentication);
    }
    filterChain.doFilter(request, response);
}

Pull the token out of the "Authorization: Bearer..." header.

If the cryptographic signature is valid, read the email address from it.

Load the user from the database and tell Spring Security: "This user is logged in for this request."

Pass the request down the chain to the actual Controller.

🎯
Interview Question: Session vs Stateless

Q: "Why did you use JWTs instead of HTTP Sessions?"
A: "Because our architecture is stateless. If we used Sessions, the server stores state in memory. If we scale Java to 3 servers, Server 2 doesn't know the user logged into Server 1. With JWT, the token itself contains the identity, meaning the user can hit any server and be authenticated."

Spring Boot Fundamentals in Action

Dependency Injection (DI) & IoC

In traditional Java, you manually instantiate objects (new Service()). In Spring, the IoC Container (Inversion of Control) manages objects, called Beans.

@Service
public class PlacementDriveService {

    @Autowired
    private PlacementDriveRepository repository;

    @Autowired
    private AiIntegrationService aiService;
}

@Service tells Spring: "Create a Singleton instance of this class on startup."

@Autowired tells Spring: "Find the Repository bean you created, and inject it into this variable automatically."

⚠️
Architecture Improvement

The code uses Field Injection (putting @Autowired directly on variables). In an interview, mention that Constructor Injection is the modern best practice. It allows fields to be final, ensuring they aren't modified, and makes writing unit tests much easier because you don't need Spring to inject mocks—you just pass them to the constructor.

Global Exception Handling

Instead of writing try/catch blocks in every single controller, Spring uses AOP (Aspect-Oriented Programming) to catch errors globally.

@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<Object> handleNotFound(ResourceNotFoundException ex) {
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("message", ex.getMessage());
        body.put("success", false);
        
        return new ResponseEntity<>(body, HttpStatus.NOT_FOUND);
    }
}

@ControllerAdvice acts as an interceptor. If any controller throws an error...

...and it matches ResourceNotFoundException, this method runs.

It creates a standard JSON response with success: false and an HTTP 404 status code.

Data Modeling with JPA/Hibernate

Mapping Objects to Tables (ORM)

Spring Data JPA uses Hibernate under the hood to translate Java objects into SQL tables. Look at how PlacementDrive is defined:

@Entity
@Table(name = "placement_drives")
public class PlacementDrive {

    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private UUID id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "tpo_id")
    private User tpo;

    @Column(name = "config_json", columnDefinition = "jsonb")
    @JdbcTypeCode(SqlTypes.JSON)
    private String configJson;
}

Create a PostgreSQL table called placement_drives.

Auto-generate a secure UUID for the primary key.

Many Drives belong to One TPO user. FetchType.LAZY means "don't query the User table until I explicitly ask for drive.getTpo()" (saves memory).

Store JSON directly in Postgres using the native jsonb format for speed and queryability.

🎯
Interview Question: N+1 Problem

Q: "What is the N+1 select problem in Hibernate?"
A: "It happens when you fetch a list of drives (1 query), and then loop through them calling drive.getTpo().getName(). If there are 100 drives, Hibernate runs 100 extra queries to fetch the TPOs (N+1 queries total). To fix it, you write a JPQL query using JOIN FETCH d.tpo to grab everything in a single SQL query."

05

Architecture Flaws & How You'd Fix Them

The "Distributed Monolith" Smell

Right now, both the Java Backend and the Python AI-Engine use the same jdbc:postgresql://localhost:5432/intervyouai database.

Why is this bad? If Java changes the User table schema, the Python code might crash. This violates the microservice principle of Database-per-Service.

The Fix to suggest in an interview:

  • Java owns the PostgreSQL DB (Users, Drives, Auth).
  • Python owns a separate NoSQL DB (e.g., MongoDB) for storing raw transcripts, FAISS vectors, and JSON feedback.
  • When Java needs feedback, Python sends it over Kafka, and Java stores only a reference or a flattened summary.

Synchronous External API Calls

In PlacementDriveService.java, when a drive is created, Java uses RestTemplate to POST to the Python engine to extract skills from the Job Description.

Why is this bad? If the Python engine is restarting, the Drive creation fails completely. It creates tight coupling.

The Fix: Create the drive with a status of PENDING_ANALYSIS. Publish a DriveCreatedEvent to Kafka. Python picks it up, extracts skills, and replies via Kafka. The UI listens via WebSockets or polling for the "Analysis Complete" update.

During a massive placement drive, 500 students upload their resumes at the exact same minute. The Python AI engine (which parses PDFs and creates vectors) gets overwhelmed and crashes. As the Java Backend Developer, how do you fix the system architecture to handle this?

A) Use RestTemplate with a retry mechanism in Java to keep hitting Python until it responds.
B) Buy a massive AWS server with 128GB of RAM so Python never crashes.
C) Java uploads the file to S3, saves status as 'Processing', and puts a message in a Kafka queue. Python pulls messages from Kafka one by one at its own pace.
