System Design & Backend Architecture

Scaling from MVP to Production in a Startup Environment

Module 1: Load Balancing & Scaling

How do you handle a sudden 10x spike in traffic?

Horizontal Scaling

Adding more servers (nodes). This is preferred for microservices. Requires a Load Balancer (Nginx, AWS ELB).

Vertical Scaling

Adding more CPU/RAM to a single server. Limited by hardware and has a single point of failure.

Tricky Question: "What is a 'sticky session' and why is it usually a bad idea?"

Answer: Sticky sessions force a user to always hit the same server. It's bad because it prevents even load distribution and makes it impossible to take a server down for maintenance without logging users out. Stateless JWTs are the better solution.

Module 2: Caching Strategies

Caching saves your database from dying. But invalidating cache is the hardest part of CS.

  • Cache Aside: App checks cache. If miss, it hits DB and writes to cache. (Most common).
  • Write Through: App writes to cache, and cache synchronously writes to DB. (Ensures consistency).
  • Write Behind (Write Back): App writes to cache; cache writes to DB asynchronously. (Highest performance, but risk of data loss).
Interview Tip: Mention Redis for distributed caching and Caffeine for local in-memory caching in Java.

Module 3: Database Sharding vs Replication

Replication (Master-Slave)

Write to Master, Read from Slaves. Increases Read scalability.

Sharding (Partitioning)

Splitting data across multiple databases (e.g., Users A-M in DB1, N-Z in DB2). Increases Write scalability.

Module 4: Microservices Communication

How do services talk to each other without becoming a "distributed mess"?

  • REST/gRPC: Synchronous. Good for instant responses but creates tight coupling.
  • Message Queues (Kafka/RabbitMQ): Asynchronous. Decouples services. If the receiver is down, the message stays in the queue. This is how you build a resilient system.
