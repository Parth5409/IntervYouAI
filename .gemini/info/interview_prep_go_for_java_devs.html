The Go Blueprint for Java Devs

Mastering Simplicity and Concurrency in a Go-First Startup

Module 1: Mental Shift - Composition over Inheritance

In Java, you think in extends. In Go, you think in Interfaces and Embedding.

type Writer interface {
    Write([]byte) (int, error)
}

type MyLogger struct {
    File *os.File // Embedding
}

Interfaces are Implicit: You don't say implements Writer. If your struct has a Write method, it is a Writer. (Structural Typing).

No Inheritance: MyLogger doesn't 'inherit' from File. It 'has' a File. This prevents deep, confusing class hierarchies.

Module 2: Pointers - Reference vs Value

In Java, everything except primitives is a reference. In Go, you decide.

  • func update(u User): Passes a copy of the user. Changes inside won't affect the original.
  • func update(u *User): Passes a pointer. Changes affect the original object.
Startup Insight: Passing by pointer is more efficient for large structs because it avoids copying data. But it also creates more work for the Garbage Collector (GC) because it might move data from Stack to Heap (Escape Analysis).

Module 3: Concurrency - Channels & Goroutines

Don't communicate by sharing memory; share memory by communicating.

ch := make(chan string)

go func() {
    ch <- "Done!" // Send to channel
}()

msg := <-ch // Receive from channel

Goroutines: Lightweight threads managed by the Go runtime, not the OS.

Channels: Pipes that connect goroutines. They handle synchronization automatically—no wait/notify needed!

Module 4: The defer Keyword

Go doesn't have try-finally. It has defer.

f, _ := os.Open("file.txt")
defer f.Close() // Runs at method end

// ... read the file

defer schedules a function call to run immediately before the surrounding function returns.

It's perfect for closing files, unlocking mutexes, or cleaning up resources.

Module 5: Project Structure (Go Modules)

No pom.xml or build.gradle. Go uses go.mod.

  • go mod init: Starts a new project.
  • go mod tidy: Cleans up unused dependencies.
  • Packages: Everything in a folder belongs to the same package. No nested package names like com.org.app.
