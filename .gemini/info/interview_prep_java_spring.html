Module 1: JVM & Memory Internals

Understanding the JVM is what separates a coder from an engineer. Startups need people who can optimize memory footprints.

Stack vs Heap

  • Stack: Stores local variables and method calls. Thread-safe and fast.
  • Heap: Stores all objects. Shared across threads. Managed by Garbage Collection.

Metaspace

Replaced PermGen in Java 8. Stores class metadata. It grows automatically and uses Native Memory.

Tricky Question: "Can an object ever be stored on the Stack?"

Answer: Yes, via Escape Analysis. If the JVM determines that an object doesn't 'escape' the method (it's not returned or passed elsewhere), it may perform Scalar Replacement and allocate the object's fields on the stack to avoid GC overhead.

Module 2: Java 8+ & Streams

list.stream()
    .filter(d -> d.isActive())
    .map(Drive::getCompanyName)
    .collect(Collectors.toList());

Streams: A sequence of elements supporting functional-style operations.

Intermediate Operations: (filter, map) are Lazy. They don't run until a terminal operation is called.

Terminal Operations: (collect, forEach, count) trigger the processing.

Warning: Never use .parallelStream() for tasks involving I/O or blocking operations. Parallel streams use a shared ForkJoinPool.commonPool(); if you block it, you slow down the entire JVM.

Module 3: Spring Bean Lifecycle

If you don't know the lifecycle, you'll struggle with circular dependencies and initialization bugs.

  1. Instantiate: Spring 'new's up the object.
  2. Populate Properties: DI happens here (Setter/Field injection).
  3. BeanNameAware / BeanFactoryAware: Giving the bean info about the container.
  4. Pre-Initialization: BeanPostProcessor.postProcessBeforeInitialization.
  5. AfterPropertiesSet: InitializingBean interface or @PostConstruct.
  6. Initialization: Custom init-method.
  7. Post-Initialization: BeanPostProcessor.postProcessAfterInitialization.
    (This is where AOP Proxies are created!)

Module 4: Spring Data JPA Performance

The N+1 Problem: You fetch 10 Users and then loop to get their Roles. Hibernate runs 1 query for users + 10 queries for roles.
Solution: Use JOIN FETCH in your JPQL or an @EntityGraph to fetch everything in one SQL JOIN.
